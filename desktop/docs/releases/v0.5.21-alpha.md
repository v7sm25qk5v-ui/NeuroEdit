# NeuroEdit v0.5.21-alpha

Fixes in-app updates on Macs where macOS runs NeuroEdit from a read-only temporary
copy (App Translocation), despite an installed copy being present in Applications.

## Update behavior

- The updater checks `/Applications/NeuroEdit.app` and
  `~/Applications/NeuroEdit.app` for one writable installed copy whose bundle
  metadata and executable match the running app exactly.
- A verified installed copy can receive **Download → Install and Restart**
  without opening a browser or dragging a replacement app into Applications.
- Ambiguous, different, symlinked or unwritable copies retain manual installation.
  Normal writable installations keep their existing update behavior.
- Project save/close guards, integrity checks and replacement rollback are unchanged.
- Retains the inserted slides and other features from v0.5.20-alpha.

this fix until the fixed version is installed once. Future updates use the fixed
path. Writable installed builds can update through Help → Check for Updates….

## Validation

Local Ruff passed; **813 tests passed** with a clean exit and two existing Qt
deprecation warnings. Nine new regression cases cover both Applications folders,
staging beside the installed copy, matching/mismatched bundles, ambiguous copies,
permissions, symlinks and normal writable launches. The patched detection also
identified the real writable installed copy while NeuroEdit 0.5.19 was running
translocated. The published Mac ZIP was also downloaded and verified through the production
updater, installed over 0.5.19 after normal quit, and successfully relaunched from
Applications without translocation. Full future GUI-button updating and
edited-project reopening remain smoke checks. Existing informational Windows
test/runtime limits remain.
